# BFD 双向转发检测仿真 — 滑雪场缆车控制网

在可控的虚拟链路上实现 BFD(RFC 5880)双向转发检测协议,模拟山顶控制柜与山脚
控制柜之间经主/备两条光纤互联的会话,支持链路故障注入并统计故障到判定断开的
检测时间,最终由上层把流量切换到备用链路。

## 快速运行

```bash
go run ./cmd/bfdsim            # 默认监听 :8080
# 浏览器打开 http://localhost:8080
```

页面提供五个区块:① 会话列表 ② 三态状态机 ③ 收发时间线 ④ 检测时间统计
⑤ 链路切换。可在顶部选择工作模式(异步/回声/按需)、故障类型(单向中断/双向
中断/时延抖动/丢包)与随机种子后重新运行。

## 目录结构

| 包 | 职责 |
|---|---|
| `internal/bfd` | BFD 协议核心:24 字节控制/回声报文编解码与合法性校验、三态状态机、定时器协商、P/F 轮询序列、回声与按需模式、检测死线 |
| `internal/sim` | 离散事件引擎(虚拟时钟+事件堆)、双链路模型(中断/抖动/丢包)、双端拓扑与上层流量切换、场景运行器与理论检测边界 |
| `internal/web` | HTTP API 与单页仪表盘(原生 JS,无外部依赖) |
| `cmd/bfdsim` | 程序入口 |

## 关键设计

### 确定性与可复现
- 单线程离散事件引擎,所有随机数来自以种子初始化的 `rand.Rand`;不使用
  `Date.now`/真实时钟/ goroutine 竞态。会话按鉴别符有序启动,同刻事件按
  "报文接收优先于定时器"排序,保证同种子逐事件可复现。

### 协议语义(对应需求)
1. **三态状态机**:AdminDown/Down、Init、Up,严格按 RFC 5880 转换表推进,
   对端状态随报文 `Sta` 字段传递。
2. **定时器协商**:发包间隔取 `max(本端 DesiredMinTx, 对端 RequiredMinRx)`,
   收包间隔取 `max(对端 DesiredMinTx, 本端 RequiredMinRx)`。
3. **检测时间** = 对端检测倍数 × 协商收包间隔;回声模式为本端倍数 × 回声间隔。
4. **参数变更走 Poll/Final 序列**:确认前沿用旧间隔,收到 F 位后一次性切换。
5. **回声模式**:以对端原样回送的回声报文做检测,异步控制报文降到 1s 低频。
6. **按需模式**:两端 D 位置位后平时不发周期报文,由主动轮询发起连通性确认。
7. **上层通知与切换**:会话 Up→Down 即回调 `TrafficSwitch`,把流量切到备用链路。
8. **报文合法性校验**:版本、长度、认证位、多点位、P/F 互斥、鉴别符等非法
   报文直接丢弃并按原因计数。

### 零误判保证
抖动采用有界平滑(EWMA)模型;丢包链路施加确定性的相邻到达间隔上限
(`MaxGap`)与连续丢失上限,使健康/劣化链路在任意种子下都不会触发误判,
而物理中断时报文被直接丢弃、不影响真实检测。检测判定另保留可配置宽限
(`DetectionGrace`)吸收调度相位。中断场景的实测检测时间均落在按协商公式
推导的理论区间 `[检测时间+宽限−间隔, 检测时间+宽限+时延]` 内。
